התחברות עם גוגל — מדריך שלב אחר שלב

הקוד בצד השרת כבר מוכן. מה שנשאר הוא להקים את האפליקציה ב-Google Cloud Console ולהוסיף את המפתחות לשירות ב-Render. הסימון בכל שלב נשמר בדפדפן — אפשר לסגור ולחזור.

1

פתיחת Google Cloud Console ויצירת פרויקט

פעם אחת בלבד

פתיחת Google Cloud Console
  1. התחברי עם חשבון הגוגל שאליו האפליקציה תהיה שייכת.
  2. בסרגל העליון לחצי על בורר הפרויקטים ← New Project.
  3. בשדה Project name כתבי שם כלשהו, ולחצי Create.
  4. ודאי שהפרויקט החדש מסומן כפעיל בסרגל העליון לפני שממשיכות.
למה זה נדרש? כל מפתחות ה-OAuth חיים בתוך פרויקט. בלי פרויקט פעיל, הכפתור ליצירת המפתח לא יהיה זמין.
2

הגדרת מסך ההסכמה (OAuth consent screen)

המסך שהמשתמשת רואה לפני שהיא מאשרת

פתיחת מסך ההסכמה
  1. אם זו הפעם הראשונה — לחצי Get started / Configure consent screen.
  2. בחרי User Type: External (אלא אם יש לך Google Workspace ארגוני).
  3. מלאי את השדות:
    App name
    Class App
    User support email
    המייל שלך
    Developer contact
    המייל שלך
  4. בשלב Scopes — זה כבר מוגדר אוטומטית ב-openid, email, profile. אין צורך להוסיף כלום, פשוט לחצי Save and Continue.
  5. בשלב Test users (אם מופיע) — הוסיפי את כתובות המייל של מי שאמורות להתחבר בזמן הבדיקה.
  6. לחצי Back to Dashboard בסיום.
מצב Testing מול Production כל עוד האפליקציה במצב Testing, רק כתובות שהוספת ב-Test users יוכלו להתחבר. כשהכל עובד — לחצי Publish app כדי שכל אחת תוכל. אפליקציה חיצונית בפרודקשן עם scopes בסיסיים בלבד (openid/email/profile) לא מחייבת בדיקת אבטחה של גוגל.
3

יצירת OAuth Client ID

כאן נוצרים ה-Client ID וה-Secret

פתיחת מסך ה-Credentials
  1. לחצי על + Create Credentials ← OAuth client ID.
  2. Application type — חייבת להיות Web application.
  3. Name — שם חופשי, למשל Class App Login.
  4. אל תסגרי את החלון — בשלב הבא ממלאים את הכתובות.
4

הוספת כתובות ההחזרה (Redirect URIs)

השלב שבו הכי הרבה שגיאות קורות

באותו חלון של Create OAuth client ID, תחת Authorized redirect URIs לחצי Add URI והדביקי את הכתובת של האתר החי:

כתובת ההחזרה — האתר ב-Render:

https://class-app-backend.onrender.com/api/auth/google/callback

Authorized JavaScript origins — כאן אסור להדביק את כתובת ה-callback. רק הדומיין עצמו, בלי נתיב ובלי / בסוף:

https://class-app-backend.onrender.com

אם מופיעה השגיאה Invalid Origin: URIs must not contain a path or end with '/' — הודבקה שם כתובת ה-callback. מחקי אותה והדביקי רק את השורה למעלה.

אופציונלי — לפיתוח מקומי בלבד:

רק אם את רוצה לבדוק גם מהמחשב שלך. האתר החי לא תלוי בזה.

http://localhost:3000/api/auth/google/callback
http://localhost:3000
  1. לחצי Create.
  2. ייפתח חלון עם Client ID ו-Client secret — לחצי Download JSON ושמרי אותו במקום בטוח, או פשוט השאירי את החלון פתוח לשלב הבא.
הכתובת חייבת להיות מדויקת לחלוטין הקידומת (https), הדומיין, האותיות הגדולות/קטנות והנתיב — הכל חייב להתאים לתו האחרון. אם מופיעה שגיאה redirect_uri_mismatch, הפתרון הוא להעתיק את הכתובת מתוך הודעת השגיאה עצמה ולהדביק אותה בדיוק כאן.
זהו הדומיין שמייצר השרת בעצמו השרת ב-Render בונה את כתובת ההחזרה מ-req.protocol ו-req.get('host') — כלומר בדיוק מהדומיין שהמשתמשת גלשה אליו — ב-Render כתובת ההחזרה תהיה https://class-app-backend.onrender.com. אם בעתיד תשני את שם השירות — עדכני את הכתובת כאן ב-Google.
5

הוספת המפתחות ל-Render

משתני הסביבה של השירות החי

השרת החי רץ ב-Render, ולכן המפתחות צריכים להיות בהגדרות השירות ב-Render — לא בקובץ .env שעל המחשב שלך. קובץ .env מקומי משפיע רק על הרצה מהמחשב.

פתיחת Render Dashboard
  1. בחרי את השירות class-app-backend.
  2. בתפריט הצד לחצי על Environment.
  3. לחצי + Add Environment Variable והוסיפי שני משתנים:
    Key
    GOOGLE_LOGIN_CLIENT_ID
    Value
    המזהה-מגוגל
    Key
    GOOGLE_LOGIN_CLIENT_SECRET
    Value
    הסוד-מגוגל
  4. לחצי Save Changes — Render יפרוס את השירות מחדש אוטומטית (יכול לקחת 1–3 דקות).
משתנה אופציונלי — קביעת הכתובת במפורש אם תרצי לכפות את כתובת ההחזרה ולא להסתמך על מה שהשרת מחשב, הוסיפי גם:
GOOGLE_LOGIN_REDIRECT_URI=https://class-app-backend.onrender.com/api/auth/google/callback
אותה כתובת בדיוק שמופיעה בשלב 4. אין חובה — השרת כבר יודע את הדומיין שלו ב-Render.
שני שמות אפשריים — אותו אפקט אם כבר יש לך ב-Render את GOOGLE_CLIENT_ID ו-GOOGLE_CLIENT_SECRET, השרת כבר משתמש בהם — אין צורך להוסיף כלום. השמות עם GOOGLE_LOGIN_ קודמים להם רק אם קיימים, ולכן עדיף להשתמש בהם כדי לא לפגוע בשימוש אחר.
הדף שלך לא מתעדכן? אם סביבת הסינון טוענת גרסה שמורה של הדף, הוסיפי לסוף הכתובת ?v=2 — כך הדפדפן והסינון יביאו את הקובץ המעודכן.
6

בדיקה שהכל עובד

שלוש בדיקות מהירות

  1. בדיקת הגדרה: פיתחי את הכתובת
    https://class-app-backend.onrender.com/api/auth/google/status
    צריך להופיע {"enabled":true}. אם מופיע {"enabled":false} — המפתחות לא נקראו ב-Render, חזרי לשלב 5.
  2. בדיקת הכפתור: פתחי את האתר (https://class-app-backend.onrender.com) — מתחת לטופס ההתחברות צריך להופיע כפתור לבן "התחברות באמצעות גוגל".
  3. בדיקת התחברות אמיתית: לחצי עליו ← בחרי חשבון גוגל ← מאשרי ← חזרה לאתר מחוברת. אם זו הפעם הראשונה, נפתחת משתמשת חדשה עם המייל של גוגל — שתופיע גם ברשימת המשתמשות שלך.
טבלת תקלות
  • redirect_uri_mismatch — הכתובת בשלב 4 לא זהה בדיוק. העתיקי את הכתובת מתוך הודעת השגיאה עצמה והדביקי אותה בגוגל.
  • Access blocked / App not verified — האפליקציה במצב Testing. הוסיפי את המייל תחת Test users, או לחצי Publish app.
  • הכפתור לא מופיע — השרת לא הופעל מחדש, או שהמפתחות ריקים.
  • "פג תוקף ניסיון ההתחברות" — עברו 10 דקות מהלחיצה. פשוט נסי שוב.
  • הדף לא נטען בגוגל — הסינון (נטפרי/אתרוג/נתיב) חוסם את accounts.google.com. יש לבקש מהסינון לאשר אותו.
