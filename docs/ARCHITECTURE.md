# תיעוד ארכיטקטורה

## מטרת החלוקה

הפרויקט מחולק לפי אחריות ברורה. כל שכבה מטפלת בסוג אחר של פעולה, ולכן קל יותר להבין, לבדוק ולתחזק את המערכת בלי ליצור קובץ מרכזי עמוס.

## שכבות המערכת

### `routes`

מגדירה את כתובות ה-API ואת סוג הבקשה. כל תחום מקבל Router נפרד, למשל מטלות, משתמשות או הודעות.

### `controllers`

שכבת הבקר מקבלת `req` ו-`res`, מפעילה את הפעולה המתאימה ומחזירה סטטוס ותשובה ללקוח.

### `services`

מכילה לוגיקה עסקית ושירותים חיצוניים, למשל שליחת מייל, תזמון הודעות והעלאת קבצים ל-Google Drive.

### `data`

מכילה את החיבור למסד הנתונים ואת פעולות הגישה לנתונים. שכבה זו אינה אמורה להחזיר תשובות HTTP.

### `middleware`

מכילה פעולות משותפות שעוברות לפני הטיפול בבקשה, כמו לוגים, בדיקת נתונים והרשאות.

### `frontend`

מכילה את `index.html`, `style.css` ו-`app.js` של הממשק. Express מגיש את התיקייה כקבצים סטטיים ולכן הקישורים אליה נשארים יחסיים.

## מסלול של בקשה

```text
Client -> server.js -> app.js -> routes -> controllers -> services -> data -> PostgreSQL
                                                                    |
Client <- HTTP response <- controller <- service result ------------+
```

## החלטות תאימות

- כתובות `/api/auth`, `/api/assignments`, `/api/milk`, `/api/notices` ו-`/api/summaries` לא שונו.
- נתיב `/` ממשיך להציג את `frontend/index.html`.
- קבצי סוד נשארים מחוץ ל-Git.
- קובץ תאימות זמני שומר על אפשרות להריץ פקודות ישנות לאחר העברת קובץ למסלול מסודר.
